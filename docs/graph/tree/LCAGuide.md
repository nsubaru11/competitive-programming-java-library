## 概要

オイラーツアーによる訪問列と深さの変化が $\pm 1$ である性質を利用し（Farach-Colton and Bender のアルゴリズム）、前処理 $\mathcal{O}(N)$、各クエリ $\mathcal{O}(1)$ で回答する。

## 特徴

- 前処理 $\mathcal{O}(N)$、クエリ $\mathcal{O}(1)$ の高速応答
- `RootedTree` のDFS前処理と LCA 用オイラーツアー列の構築は、どちらも明示スタックを使う反復処理
- 半分の対数を基準にしたブロック分割と、深さ増減パターンごとのブロック内 RMQ 表

## API

### 1. コンストラクタ

| コンストラクタ         | 説明                                                     |
|------------------------|----------------------------------------------------------|
| `LCA(RootedTree tree)` | 根付き木を受け取り、LCA クエリ用のデータ構造を前処理構築 |

### 2. クエリ

| メソッド                 | 戻り値の型 | 説明                                   |
|--------------------------|------------|----------------------------------------|
| `lca(int u, int v)`      | `int`      | 頂点 `u` と `v` の最小共通祖先を返す   |
| `distance(int u, int v)` | `long`     | 頂点 `u` と `v` 間の重み付き距離を返す |

## 制約・注意事項

- コンストラクタ呼び出し時に `tree` 内の全辺が追加済みである必要がある。
- 木の頂点番号は `0` から `n - 1` の 0-indexed である。
- `RootedTree` の DFS 情報は最初の参照時に遅延構築され、その後 LCA 用のオイラーツアー列を別途構築する。どちらの走査も再帰呼び出しを使わない。
- 辺は `LCA` の構築前に全て追加すること。`RootedTree` の前処理後は木を変更しないこと。
- パスクエリや部分木更新・k-th ancestor などの多様な操作が必要な場合は、[`HLD`](../../../src/lib/graph/tree/HLD.java) の利用も検討すること。

## 性能特性

- **前処理時間**: $\mathcal{O}(N)$
- **クエリ時間**: $\mathcal{O}(1)$
- **空間計算量**: $\mathcal{O}(N)$
