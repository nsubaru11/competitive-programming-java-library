# ローカル検証

`lib` の公開 API を JUnit Jupiter で検査する。実行方法は [テスト・利用例の構成](../README.md#コマンドライン) を参照する。雛形は親リポジトリの `templates/java/Test.java` である。[ds/fenwick](./ds/fenwick) が以下の構成の見本である。

## 配置と命名

- `lib` の package に対応するフォルダへ置く。例えば `lib.ds.map` のテストは `test/unit/ds/map/` に置き、package は `unit.ds.map` とする。
- `lib` の1クラスに対してテストも1クラス・1ファイルとし、クラス名は `<対象>Test` とする。例: `IntBITTest`。既存の `PriorityQueueTest` のように、Guide の単位で型別クラスをまとめたものもある。
- クラス名を `Test` にしない。`@Test` が自分自身のクラスを指してコンパイルエラーになる。
- テストはバンドル対象外のため、`import static org.junit.jupiter.api.Assertions.*;` を使ってよい。

| ファイル                   | 内容                                                                           |
|----------------------------|--------------------------------------------------------------------------------|
| `<対象>Test.java`          | 対象クラスのテスト。型別クラスでは契約テストを継承し、その型だけの性質を加える |
| `<種類>Contract.java`      | 型別クラス（generic・`int`・`long`）に共通する振る舞いのテスト。抽象クラス     |
| `Naive.java`               | モジュールの愚直解。照合に使う                                                 |
| `support/RandomOperations` | 愚直解との照合で、操作をランダムに選んで実行する共通の仕組み                   |

## テストクラスの構成

テストクラスの中は、`@Nested` の内部クラスで API のグループに分ける。グループと並び順は AGENTS.md のメソッドの並び順に合わせ、該当するメソッドがないグループは作らない。IntelliJ IDEA のテスト結果がこのグループのツリーで表示され、テストのないメソッドを見つけやすくなる。

| `@Nested` クラス | 対象                                                         |
|------------------|--------------------------------------------------------------|
| `Construction`   | コンストラクタ、コピーの独立性                               |
| `State`          | `size`・`isEmpty` などの状態                                 |
| `Access`         | `get` などの読み取り                                         |
| `Updates`        | `set`・`add`・`multiply`・`affine`・`apply` などの要素の更新 |
| `Bulk`           | `fill`・`setAll`・`clear`                                    |
| `Aggregation`    | `sum`・`query` などの集計                                    |
| `Search`         | `lowerBound`・`upperBound` などの探索                        |
| `Transformation` | `swap`・`reverse` などの変形                                 |
| `Conversion`     | `toArray`・`iterator`・`forEach*`・`toString`                |

範囲外の添字で投げる例外は、そのメソッドのグループに置く。愚直解との照合（`matchesNaive`）は `@Nested` に入れず、テストクラスの直下に置く。

## 型別クラスの契約テスト

generic・`int`・`long` 版に共通する振る舞いは、`<種類>Contract` の抽象クラスに1回だけ書く。

- 契約テストは、値を `long` で受け渡す `Target` インターフェースと、`create` などの抽象メソッドを持つ。各版のテストは、`Target` を実装する private な record と `create` を書く。
- `@Nested` クラスも契約テストに書く。継承した各版のテストで、それぞれ実行される。
- `int` 版は `Math.toIntExact` で変換し、範囲外の値を渡したら例外で気づけるようにする。
- 型に固有の性質（`int` 版の和が `long` になる、`long` 版が `int` の範囲を超える値を扱えるなど）は、各版のテストクラスの直下に書く。
- 引数や戻り値の形が違い、共通化すると読みにくくなるクラス（例: 半開区間を使う `BIT`）は、契約テストを使わずに単独で書く。

## テストの種類

| 種類           | JUnit の機能                                  | 方針                                                                                        |
|----------------|-----------------------------------------------|---------------------------------------------------------------------------------------------|
| 境界値・具体例 | `@Test`、`@ParameterizedTest` と `@CsvSource` | 空区間、先頭・末尾、0 を含む値など、Guide に記載した前提条件の範囲内の境界を検査する        |
| 愚直解との照合 | `@RepeatedTest` と `RandomOperations`         | 配列や `java.util` などの単純な実装と同じ操作列を適用して比べる。シードは繰り返し番号とする |
| TLE 検出       | `@Tag("slow")` と `@Timeout`                  | 最大制約の入力で実行時間を検査する。`./gradlew slowTest` だけが実行する                     |

`RandomOperations` には、操作を名前と重みで登録する。失敗メッセージにはシード・操作番号・操作名が入る。一度も選ばれなかった操作があると失敗するため、照合されていない操作を見逃さない。

ライブラリが検査しない不正入力のテストは書かない。テストするのは Guide と Javadoc に記載された振る舞いだけである。

## 網羅率

`./gradlew test` のあと、`build/reports/jacoco/test/html/index.html` で行と分岐の網羅率を確認する。網羅されていない行や分岐があれば、Guide と Javadoc に記載された振る舞いかを確かめ、記載があればテストを足す。記載のない使い方（例: `BIT` の単位元に `null` を渡す）のためだけにテストを足さない。
